# 2026-10-06 进度：接上真实 Qloo 黑客松 API 后的修复

## 起因

Shelfwise 切到 live 模式（Dell 上 `shelfwise` 容器，QLOO_BASE_URL=https://hackathon.api.qloo.com）后，实测发现四个问题，外加侧栏两个空按钮。

## 修了什么

### 1. trends 对书报 400（每次 live 都有两条红色错误）

- 原因：黑客松 API 的 `/v2/trending` 只接受 actor/artist/brand/movie/person/podcast/tv_show，书直接 400；而 prompt 让模型对前 5 本书查趋势。工具 schema 里仍列着 book，所以光看 schema 发现不了。
- 改法：趋势改为查“读者喜欢的东西”（剧、电影、歌手、播客），按类型一类一调，不再对书查。
  - `src/qloo/validate.ts`：新增 `TREND_ENTITY_TYPES`，`qloo_trends` 的 `entity_type` 不在其中就在调用 Qloo 之前拒绝，并告诉模型改查哪些类型。
  - `src/agent/prompt.ts`：第 5 步改成可选的“对 tv_show/movie/artist/podcast/person/brand 信号查趋势”；规则 3 写明书永远不能说 rising/fading/steady，方向词只能说给趋势条目里那个实体。
  - `src/agent/guard.ts` + `src/shared/types.ts`：买书清单每本书新增 `signalTrends`，即“带出这本书的那个信号”的趋势；书本身的 `trend` 保留但 live 下为空。
  - `web/src/components/BuyList.tsx`：Trend 一栏显示“Interest in <信号> 上升/平稳/下降”；没有时写明 Qloo 没有书的趋势数据。
  - `src/agent/trend.ts`：顺带修了一个真 bug。live 趋势点的字段是 `date, population_percentile, population_rank(字符串), population_rank_velocity, velocity_fold_change, population_percent_delta`。旧的兜底正则 `/lat|lon|rank|id$/` 把 “popu**lat**ion” 当成纬度排除，结果会拿 `velocity_fold_change`（变化率）去算方向。现在优先用 `population_percentile`，并排除 velocity/delta/fold_change 这类变化率字段。
  - 样例模式保持一致：`src/qloo/fixtures/data.ts` 把编造的趋势从书挪到信号上（游戏和书没有），`fixtures/client.ts` 对不支持的类型返回与 live 相同的 400，`src/agent/demo-llm.ts` 按信号类型查趋势，理由写成“interest in {信号} is rising”。

### 2. where_popular 显示 “returned 0 items”

- 原因：harness 成功时不带 `summary`，回落到 `defaultSummary()`，而它没看热力图区域数。
- 改法：`src/agent/evidence.ts` 的 `defaultSummary()` 优先用 `rec.local.summary`（“Qloo returned 10 areas within Newark, NJ; the strongest has affinity …”），其余工具回落到 `result_count`。

### 3. 模型给 qloo_rank 传 `limit` 被拒

- `src/qloo/validate.ts` 新增 `stripHarmlessArgs()`：只在工具 schema 没有 `limit` 时去掉它（rank 本来就返回全部选项），并在给模型的结果里注明 “Ignored argument "limit"”。其它未知参数照旧拒绝，不掩盖真错误。
- prompt 第 3 步写明 qloo_rank 没有 limit。

### 4. 实体类型显示成 “urn:entity”

- 原因：harness 把 Qloo 结果的 `type`（裸的 `urn:entity`）和 `subtype`（`urn:entity:book`）都透传，旧代码只读 `type`，UI 显示成 “Entity”。
- 改法：`evidence.ts` 新增 `entityTypeOf()`，取 subtype/type/types 里最具体的；`normType("urn:entity")` 返回 undefined，回落到调用的 target_type。`web/src/lib/format.ts` 的 `entityTypeLabel` 对裸 `urn:entity` 不显示标签。

### 5. live 复测时新发现的两处（已修）

- 模型给 `qloo_rank` 传了 16 个选项，schema 上限是 10，被拒后模型自己改成 10 个重试成功，但轨迹里留了一条红色错误。prompt 第 3 步改成“最多 10 本，多的丢掉，因为 qloo_rank 超过 10 个会被拒”。之后两次 live 都只传 ≤10 个。
- live 的 affinity 有十几位小数（0.9432074816979662），样例数据都是两位所以之前没暴露。新增 `src/shared/affinity.ts` 的 `formatAffinity()`，只在显示处保留两位：where_popular 摘要、引用按钮文字（guard.ts）、轨迹行、买书清单。证据里仍存原值。

### 6. 侧栏 Recent runs / Print desk（subagent 实现，我做验收和两处小修）

- 新文件：`web/src/lib/recentRuns.ts`（localStorage `shelfwise-recent-runs`，最近 10 条、新的在前、按 sessionId 去重、所有读写 try/catch、只存完成的 run，原始 Qloo 结果不存）、`hooks/useRecentRuns.ts`、`hooks/useNow.ts`、`components/RecentRuns.tsx`、`components/PrintDesk.tsx`、`web/test/recent-runs.test.ts`。

- 我改的两处：Recent runs 的受众取报告里的受众（追问“改成青少年”后表单和报告不一致）；存档 run 里 “Raw Qloo result” 的说明文字按普通文字显示，不再带 JSON 引号。

- headless Chrome 走 CDP（nice 19，每个页面单独开一个、测完就关）。光标停在内容栏，用 `Input.synthesizeScrollGesture` 分段轻扫，先下滑再上滑；每次轻扫后补一次 mousemove，模拟 Chrome 滚动停下后重新判定 hover。

  - 普通元素每帧的位移必须正好是 −Δscroll；

  - 超出上面范围 0.5px 以上记一次“抖动”。
- 同时记录 layout-shift 和 long-animation-frame。

## 根因

1. **talker 卡片 hover 上移 2px（主因）。**
   - redesign.css 第 129 行的全局 `transition` 列表覆盖了 results.css 里的 transform 过渡，所以卡片上移是瞬间跳 2px，阴影再花 320ms 渐变。
   - 用触控板滚动时，卡片一张张滑过静止的光标，每张都跳起来再落回去，看起来就是“晃”。
   - 对照组（光标在侧栏）是 0，可以确定是 hover 引起的。主按钮 hover 上移 1px 也是同一个原因。
2. **样例模式下侧栏滑到横幅下面。**
   - 侧栏 sticky `top: 0`，横幅 sticky 34px。滚动约 34px 后，侧栏滑到横幅下面才停住，品牌标识上边 11px 被盖住（508 帧里有 416 帧这样）。
   - 这不算抖动，但看上去是“先往上走一下再停”。live 模式没有横幅，不受影响。
3. **查过、没有问题的：**
   - 所有滚动场景的 layout shift 都是 0；
   - 代码里没有 filter / backdrop-filter；
   - 390 宽触摸滚动 0 抖动。
4. **dvh：**
   - 剩下的 dvh 只有两处：证据面板 sticky 的 max-height 和手机底部抽屉的 82dvh。`.app` 的 min-height 其实已经被 redesign.css 覆盖成 100vh。
   - headless 模拟不出地址栏收起，所以这一条是按代码改的，没有实测。

  - 去掉 `.talker:hover` 的 `translateY(-2px)` 和 `.btn--primary:hover` 的 `translateY(-1px)`。hover 只改边框色和阴影。
  - 0.32s 的颜色过渡只在 `html.theme-fading` 下生效。
